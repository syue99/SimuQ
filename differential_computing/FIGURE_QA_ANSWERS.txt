Q1 — THE r GENERATOR
================================================================================

(a) "One r per dialed theta, shifted NSR branches not re-rounded"
    NO — neither half matches the code.

There is no "one r per dialed theta".  Every builder draws TWO INDEPENDENT
Gaussians per FD gradient component, per estimate — one for each arm — freshly
from the trial RNG:

  tests/build_F6.py:234        dp, dm = rng.normal(0, R_CTRL), rng.normal(0, R_CTRL)
                               then  theta0+eps+dp  /  theta0-eps+dm
  same shape at:
    build_Floop.py:120,  build_Floop_real.py:174,  build_Floop_landscape.py:161,
    build_Floop_multiP.py:167, build_Floop_direction.py:132,
    build_fig1.py:145,169,     landscape_device.py:87,
    build_Floop_trajectory.py:145-146

Properties of the draw as coded:
  * NOT keyed to theta, not cached, not hashed.  The SAME dialed theta visited
    twice in a descent gets two DIFFERENT delta values.
  * Independent between the + and - arms (NOT common-mode).
  * Independent across gradient components and across iterations.
  * The base operating point theta0 is NEVER jittered — only the two probe
    offsets are.

And the shifted branches: PSR AND NSR NEVER SEE delta AT ALL in any builder.
  build_F6.py:167-214  nsr_est / nsr_trunc_est / nsr_rej_est evaluate
                       Cint(theta0 + shift) with no delta term.
  build_F6.py:151      psr_est samples the branch expectations directly.
So "shifted NSR branches not re-rounded" is true only in the trivial sense that
they are never rounded or offset in the first place.

(b) Is 0.02 the resolution grid or a bound on |r|?
    NEITHER.  0.02 is the STANDARD DEVIATION sigma of a zero-mean Gaussian.

  R_CTRL = 0.02  feeds  rng.normal(0, R_CTRL)  everywhere.
  |delta| is unbounded; ~32% of draws exceed 0.02 in magnitude.
  build_F6.py:98-99 (comment) and the predicted-floor Monte Carlo at
  build_F6.py:244-248 both treat it as sigma.

(c) How is r(theta) actually produced?
    A per-call draw from the builder's seeded np.random.default_rng stream —
    closest to "hash-seeded draw with scale 0.02", minus the hash.  Seeded per
    trial / per descent seed, so runs reproduce exactly; it is NOT rounding to a
    0.02 grid and NOT a per-theta memoized value.

--------------------------------------------------------------------------------
CONSEQUENCE: the appendix T4 model cell is currently WRONG
--------------------------------------------------------------------------------
Paper_writing/appendix_2.tex:988-991 says:
   "a DETERMINISTIC coefficient offset theta -> theta + r fixed per operating
    point, not a per-shot draw"
   "ALL STRATEGIES execute at the offset setpoint; only FD divides by it"
Both clauses contradict the emulator.

Knock-on, appendix_2.tex:997-1010:
  * "it survives averaging because it is not a fluctuation" — true only of a
    deterministic offset.  Under the code the delta/eps term IS a zero-mean
    fluctuation: it survives SHOT averaging (it is a landscape-argument error,
    not a binomial one) but would average down over independent re-programmings.
  * "NSR and PSR remain exactly unbiased for the offset landscape C(theta+r)" —
    describes a model the code does not run.  In the code PSR/NSR see no offset
    at all and are unbiased for C at the exact theta.

Model cell rewritten to match the code:

   control setpoint error r — an i.i.d. zero-mean Gaussian offset
   delta ~ N(0, r^2), r = 0.02, drawn independently for each programmed probe
   setpoint (each FD arm, each component, each estimate).  Touches FD only:
   PSR/NSR are eps-free and execute at the nominal setpoint.  FD converts it
   into a gradient error
        sqrt( C'(theta+eps)^2 + C'(theta-eps)^2 ) * r / (2 eps),
   an irreducible RMSE floor that no number of shots removes.

That expression is literally F6's predicted floor, build_F6.py:99.

--------------------------------------------------------------------------------
GKLS NORMALIZATION: gamma multiplies (1/2)(Z rho Z - rho)
--------------------------------------------------------------------------------
noise_model.py:164-177 builds the collapse operator

        c = sqrt(gamma_phi / 2) * Z ,      gamma_phi = 1/T2*

so the master-equation term is

        D[c] rho = c rho c^dag - (1/2){c^dag c, rho}
                 = (gamma_phi/2) (Z rho Z - rho),     gamma_phi = 1/T2*

and coherences decay as rho_01(t) = rho_01(0) exp(-gamma_phi t) = exp(-t/T2*).
T2* is the 1/e coherence time, full stop.

So T/T2* = 0.15 means a coherence factor exp(-0.15) = 0.861 over the segment —
NOT exp(-0.30) = 0.741, which is what the other convention (gamma (Z rho Z - rho)
at gamma = 1/T2*) would give.  Recommend writing the dissipator explicitly in the
cell rather than "at 1/T2*", since that phrase reads either way.

THE 33 us CROSS-CHECK PASSES; T4.csv's DEFAULT CELL DOES NOT
--------------------------------------------------------------------------------
F6 sets T = 5.0 us and T2 = T/0.15 (build_F6.py:40-41) -> T2* = 33.3 us, matching
App E's "dressed T2 ~ 33 us at the 5.0 us segment" exactly under the (1/2)-
convention above.

But T4.csv / tests/sec6_T4_noise_table.py:26-29 states the default as
"T2* = 5.0 us ... T = T/T2* * T2*", i.e. T2* fixed and T derived, which would
give T = 0.75 us.  The code does the OPPOSITE: T is each figure's segment
duration and T2* is DERIVED from the held ruling T/T2*.  Consequently T2* is not
one number across the figure set:

    figure                        T (us)   T/T2*    T2* (us)
    F6                              5.0     0.15      33.3
    F_loop (build_Floop*.py)        1.5     0.15      10.0

    Fig 1                          12.0     0.5       24.0
    landscape_device (legacy F3)   10.0     0.5       20.0

T4 can honestly quote the RATIO as the ruling plus one worked instantiation
(F6: 5.0 us / 33.3 us), but it cannot quote "T2* = 5.0 us" as a device default —
that number appears nowhere in the emulator.
